# L3 · exposure_state — 노출 규칙의 현재 상태를 읽는다

> **Single-role unit.** Independent — no ordering; an L2 calls it when needed. Does ONE thing.
> 엔진 = `scripts/exposure_rule.py`. 이 유닛은 **읽기**만 한다 — 적립(`log`)은 타임폴리오
> 스케줄 태스크(09:10·15:00)가 소유한다. 리서치 런이 원장에 하루 두 번 이상 쓰면 안 된다.

- **Role**: "지금 우리는 얼마나 노출해야 하는가"를 **규칙이 답하게 한다.** 종목을 고르는 스테이지가
  **투자 총량을 모르는 채** 이름을 고르면, 그 이름들이 어느 비중으로 들어갈지는 아무도 정하지 않은
  것이 된다 — 2026-07-31 에 실제로 일어난 일이다.
- **Input**: 없음(벤치 `069500.KS` + `data/exposure_bands.json`). 계좌 조회는 **하지 않는다**
  (브라우저 없이 장 전에도 돌아야 한다).
- **CLI**:
  ```bash
  python -X utf8 scripts/exposure_rule.py state          # 오늘 판정 (적립 안 함)
  python -X utf8 scripts/exposure_rule.py target --json  # {state, invested_target_pct, cash_target_pct}
  python -X utf8 scripts/exposure_rule.py show --tail 10 # 적립 원장 + 누적 분해
  ```
- **Output**: 4상태 중 하나(`정상`/`방어`/`복귀`/`과열`) + 목표 투자비중 + 현금 목표비중.
  **현금 타깃의 단일 원본**(F5) — `module_timefolio._sync.apply_exposure_rule` 이 이걸 읽는다.

## 왜 리서치 런이 이걸 읽어야 하나

측정된 것(`HARNESS_UPGRADE_20260731.md §1-c`): 벤치 대비 **+16.86pp 중 약 14pp 가 현금비중**이고,
**종목선택은 +2.54pp — 한 종목이 대부분이고 n=11, 창 1개 ⇒ 0과 구분 불가(C4)**.
그리고 그다음 세션에 **같은 현금비중이 −12.5pp** 를 반납했다.

⇒ **이 데스크가 실제로 하는 일은 베타 관리다.** BET/ALPHA 가 이름을 고를 때 노출 상태를 모르면,
`방어`(투자 55%)인 날에도 `복귀`(90%)인 날과 같은 크기의 후보 목록을 낸다. 그건 사이징이 아니다.

## 상태별로 무엇이 달라지나 (BET·ALPHA 가 읽는 방식)

| 상태 | 뜻 | 후보 목록에 대한 함의 |
|---|---|---|
| `정상` | 발화 조건 없음 | 평시 폭 |
| `방어` | 20일 고점 대비 임계 이탈 | 신규 진입 폭을 좁히고 **기존 유지**를 우선 |
| `복귀` | ★ 돌아섰다는 **증거** 3다리 충족 | **신규·증량 후보가 필요하다** — 목표 비중이 크게 오르므로 BET 이 후보를 못 내면 현금이 남는다 |
| `과열` | 20일MA 대비 임계 초과 | 신규는 좁히되 청산은 규칙이 아니라 종목 근거로 |
| `밴드미설정` | `data/exposure_bands.json` 없음 | 🚨 **판정 없음.** 목표를 지어내지 말고 그대로 보고 |
| `복귀판정보류:X` | 장중이라 거래량 다리를 못 잼 | 🚨 직전 상태 X 를 유지. **거짓이 아니라 판정불가**(C3) |

## ⚠ 이 유닛을 부를 때 반드시 함께 읽을 것

- **`bar_status`** — `live` 면 미정착 봉이다(D74). 장중 판정은 잠정이고, 종가 후 값이 달라진다.
  실측 2026-07-31 10:3x: yfinance `103,625` vs KIS `102,545` (**1.05% 괴리**) — 장중 벤치는 KIS 가 1차.
- **원장이 비면 냉시동한다.** 상태는 **경로 의존**(복귀는 방어에서만 발화)이라, `out/exposure/ledger.csv`
  가 비어 있으면 첫 실행이 `prev_state=정상` 으로 출발한다. 실측 2026-07-31: 그 냉시동 때문에
  `방어`(괴리 −1.9pp)로 찍혔고, `backfill` 후 다시 돌리니 **`복귀` · 괴리 −37.2pp 🚨밴드이탈** —
  **경보를 통째로 삼켰다.** `show` 에 행이 없으면 `backfill` 을 먼저 부르고 그 사실을 적어라.
- **밴드 숫자는 사람이 정한다**(P5). 이 유닛도, 이 유닛을 부르는 어떤 스테이지도 숫자를 채우지 않는다.

## 회전 비용 — 이 규칙은 공짜가 아니다

`simulate` 가 상태 전이마다 `|Δ목표비중|` 을 더해 **주당 회전 pp** 를 같이 낸다. 실측
(069500.KS 120세션, '공격' 밴드):

| 최소유지 | 상태 전이 | 누적 회전 | 주당 | 복귀 발화 |
|---|---|---|---|---|
| 0세션 | **36회** | 1040pp | **43.3pp** | 7회 |
| 2세션 | 20회 | 520pp | 21.7pp | 2회 |
| **3세션 (채택)** | **18~19회** | 470~510pp | **19.6pp** | 3회 |
| 5세션 | 15회 | 400pp | 16.7pp | **0회 ← 규칙이 죽는다** |

게이트 없이는 **노출 규칙 하나가 데스크 전체 주간 회전율(실측 26.9%)의 1.6배**를 종목 매매
전에 써버린다. 콘테스트 누적 위반은 이미 1건이다.
⚠ **그리고 3세션은 이 프로젝트를 만든 사건에 비용이 0이다** — 07-30 상태가 오래된 `방어` 라
최소유지 0·2·3·5 **전부** 07-31 을 `복귀` 로 판정한다. 잃는 것은 휩소뿐이다.
⚠ 전이가 보류되면 상태가 아니라 **근거 문자열**에 `⚠전이 보류(A→B) — 최소유지 k/3세션` 이
붙는다. 보류를 "조건 미충족"으로 읽지 마라 — 조건은 충족됐고 **집행만 미룬 것**이다.

## 종목 상한은 이 유닛이 아니라 `module_timefolio._sync` 가 건다

노출 규칙은 **총량**만 정한다. 그 총량을 종목에 나누는 순간 콘테스트의 종목별 상한
(기본 15% · 005930 40%)이 걸리는데, 재정규화는 상한을 모른다 — **투자 90% 에 종목이 7개
미만이면 균등 배분만으로도 상한을 깬다**(산술). `_sync._apply_caps` 가 깎고 재배분하며
**깎인 내역을 전부 출력한다**(조용히 깎지 않는다). 재배분할 여유가 없으면 남는 %p 는
현금으로 남고 그 사실도 적힌다.
