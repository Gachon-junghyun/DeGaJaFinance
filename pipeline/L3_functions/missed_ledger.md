# L3 · missed_ledger — 사지 않은 것을 적립하고 채점한다

> **Single-role unit.** Independent — no ordering; an L2 calls it when needed. Does ONE thing.
> **[reject_ledger](reject_ledger.md) 의 대칭 짝.** 둘은 같은 벤치·같은 노이즈밴드(±5pp)·같은
> 유형 3분류를 쓴다 — 그래야 두 원장을 **나란히 놓고 합산**할 수 있다.

- **Role**: 데스크가 **보고도 사지 않은 것**을 자산으로 만든다. 거부는 2026-07-23부터 채점되는데
  **미진입은 어느 숫자에도 남지 않았다**(F2). 남지 않으면 개선되지 않는다.
- **Input**: 미진입 1건 (날짜 · 티커 · 종목명 · 사유클래스 · 근거 한 줄 · 스테이지 · **진입조건** ·
  **재확인일**) 또는 채점/감사 요청.
- **CLI**:
  ```bash
  python -X utf8 scripts/missed_ledger.py add --date 2026-07-24 --ticker 051900 \
      --name LG생활건강 --cls O.커버리지소실 --why "이전 런엔 있었고 이번 런 산출물에서 사라짐" \
      --stage SWEEP --enters-if "소비재 로테이션 OW 전환 ∨ OBV 매집 재확인" --recheck-date 2026-08-07
  python -X utf8 scripts/missed_ledger.py score      # 전체 채점 + 클래스/유형 집계 + 대칭 확인
  python -X utf8 scripts/missed_ledger.py due        # ★ 재확인일 도래/경과 + 진입조건 없는 항목 감사
  python -X utf8 scripts/missed_ledger.py resolve --ticker 051900 --date 2026-07-24 \
      --outcome entered --note "..."                 # append-only, 원 행 미변경
  ```
- **Output**: `out/missed_ledger.jsonl` + `out/missed_ledger_resolutions.jsonl` + 채점표.

## ★ 부호가 반대다 — 이 유닛을 읽을 때 가장 자주 틀리는 지점

| | `reject_ledger` | `missed_ledger` |
|---|---|---|
| `excess > 0` | **거부가 손해** (버렸는데 올랐다) | **놓쳐서 손해** (안 샀는데 올랐다) |
| `excess < 0` | 거부가 이득 | 안 사서 이득 |

두 원장의 `excess` 를 그냥 더하면 안 된다. **부호를 맞춘 뒤** 합산하라.

## 거부와 미진입을 가르는 선 — `add` 가 기계로 강제한다

`add` 는 같은 **티커 × 날짜**가 `reject_ledger` 에 이미 있으면 **거부한다**(exit 1).
같은 사건을 두 원장이 각각 세면 합산이 거짓말이 되기 때문이다.

- **거부** = 다뤘고, 사유를 적었고, 명시적으로 버렸다 → `reject_ledger`
- **미진입** = 거부라고 말할 만큼도 다루지 않고 지나갔다 → 여기

⚠ **실측 정정(2026-07-31)**: 인수인계 문서는 *"한미반도체 +27.4% 를 놓친 게 어느 숫자에도 안 남는다"*
고 적었으나 **틀렸다** — 042700 은 `reject_ledger` 에 2건(07-14 C.차트붕괴 · 07-16 E.상관가드) 있고
채점되고 있었다. F2 의 본체(미진입 자체를 재는 장치 부재)는 유효하지만, **예시를 확인 없이 옮기면
없는 구멍을 메우게 된다.**

## 사유 클래스 — 거부 원장과 같은 3유형으로 접힌다

| 유형 | 클래스 | 뜻 |
|---|---|---|
| `measured` | `M.숏리스트탈락` · `T.사이즈미미` | **관측값**이 미진입 근거 |
| `structural` | `N.유니버스부재` · `O.커버리지소실` · `P.현금부족` · `U.발굴부재` | **구조**가 미진입 근거 |
| `narrative` | `Q.확신부족` · `R.타이밍대기` · `S.테마회피` | **이야기**가 미진입 근거 |

`P.현금부족` 은 [exposure_state](exposure_state.md) 와 직결된다 — 노출 규칙이 막아서 못 산 것은
종목 판단 실패가 아니라 **베타 결정의 비용**이고, 그 비용은 노출 원장 쪽에서 채점돼야 한다.

## ★ 표본 층(`--sample`)이 이 원장의 1급 필드다 — 층을 섞은 평균은 뜻이 없다

| 층 | 뜻 | 쓸 수 있나 |
|---|---|---|
| `prospective` | **결정 시점에** 사전 기록(오르기 전) | ✅ 유일하게 엣지 추정 가능 |
| `random` | 사후지만 클래스별 **무작위 추출** | △ 클래스 비교엔 가능 |
| `outcome_selected` | 사후 **상승 상위**에서 추출 | 🚨 평균이 구조적으로 양수 — 추정 금지 |

`score` 가 층별로 나눠 집계하고, `prospective` 가 0건이면 그 사실을 경고로 찍는다.

## ⚠ 첫 관측 (2026-07-31) — **층을 나누자 결론이 뒤집혔다. 이게 이 필드가 있는 이유다**

처음 6건을 `leak_scan --top`(상승 상위)에서 뽑아 적재하고 *"커버리지소실 +23.4pp 가 최악의 누수"*
라고 읽었다. 같은 감사에서 **클래스별 무작위 6건씩(n=24)** 다시 뽑으니:

| 클래스 | **무작위 n=24** | 결과선택 n=6 |
|---|---|---|
| `M.숏리스트탈락` | **+6.51pp** | +17.99 |
| `U.발굴부재` | +3.94pp | +14.96 |
| `Q.확신부족` | −1.20pp | — |
| **`O.커버리지소실`** | **−5.04pp** | **+23.41 (1위)** |
| 전체 | **+1.05pp** | +19.69 |

**커버리지소실은 최악의 누수가 아니라 안 사서 이득인 유일한 클래스다.** 전체 기회비용도
+19.7pp 가 아니라 **+1.05pp = 노이즈 밴드(±5pp) 안**이다.
⇒ **상승 상위에서 뽑은 표본은 원장이 아니라 후회 목록이다.** 적재는 무작위 또는 사전등록으로 한다.

⚠ 그리고 이 뒤집힘은 `leak_scan` 쪽에서도 재현된다 — 같은 07-20 창을 지평만 늘려 재채점하면
`B.커버리지소실` 이 **+1.93pp(최악) → −4.68pp(최선)** 로 뒤집힌다. 리포의 상시 주장
*"보유가 샌다"* 는 그래서 **철회됐다**(L1 [leak_audit](../L1_stages/leak_audit.md) 참조).

## 진입조건(`--enters-if`)이 이 원장의 핵심 필드다

`reject_ledger` 의 `--revives-if` 와 같은 자리다. 조건 없는 미진입은 **영구 관망**이고, 영구 관망은
영구 금지만큼 과하다 — 거부 원장에서 조건 없이 버려진 SK이터닉스가 원장 전체 손해의 대부분(+41.2pp,
+26.9pp)을 냈다는 것이 이미 실측됐다. **같은 실수를 반대편에서 반복하지 않기 위해 `add` 가 강제한다.**
