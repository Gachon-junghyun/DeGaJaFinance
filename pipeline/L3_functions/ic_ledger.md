# L3 · ic_ledger — 신호 축의 IC 를 적립한다 (이 데스크의 **시계**)

> **Single-role unit.** Independent — no ordering; an L2 calls it when needed. Does ONE thing.
> 엔진 = `scripts/ic_ledger.py`. 축 생산자는 `scripts/axis_inflection.py` 등 **따로**다.

- **Role**: "이 데스크의 신호에 부호가 있나"를 **연 단위가 아니라 월 단위로** 답할 수 있게 만든다.
- **Input**: 없음(`SECTOR_FLOW_*.json` 런 산출 + `sector_flow` 가격 캐시 + 선택적 축 파일).
- **CLI**:
  ```bash
  python -X utf8 scripts/ic_ledger.py log      # 해소된 (런×축×지평) 전부 적립(멱등)
  python -X utf8 scripts/ic_ledger.py score    # IC 시계열 + 겹침보정 + 다중비교 + 필요n
  python -X utf8 scripts/ic_ledger.py show --tail 20
  ```
- **Output**: `out/ic/ledger.csv` (런×축×지평 1행) + 축별 `평균IC · t(NW) · n_eff · **t=2까지 필요n**`.

## 왜 이 유닛이 존재하나 — 산술 하나

실력을 **11개 포지션 손익**으로 배우면 월 11관측이고, IC 0.06 을 검출하는 데 **수십 년**이 걸린다.
같은 신호를 **828종목 횡단면**으로 재면 **관측 1개 = 런 1개** ⇒ **3~5개월**이면 축마다 부호가 갈린다.
**시계가 75배 빨라진다.** 이 데스크가 반년 동안 "알파가 있나"에 답 못한 이유가 이 한 줄이다.

`필요n = (2·sd/|평균IC|)²` 이 **어느 축을 언제 죽이거나 살릴지** 알려준다 — 하루 1관측이므로
`필요n ÷ 21 ≈ 개월 수`. 이 열이 이 표의 요점이지, IC 값 자체가 아니다.

## ⚠ 이 유닛이 스스로에게서 잡아낸 함정 (전부 실측 2026-07-31)

1. **겹침 = 거짓 양성.** 일별 런의 h일 선행창은 서로 겹친다. 보정 없이 재면 h=10 이
   **`n=3 · 양수 100% · t=+6.7`** 로 나오는데, **그 3개 창은 전부 07-31 반등 하나로 끝난다** —
   같은 사건을 세 번 센 것이다. ⇒ **NW(lag h−1) + `n_eff = n/h`, `n_eff<4` 면 판정하지 않는다.**
   현재 21칸 중 **14칸이 이 사유로 판정 불가**다. 인용하지 마라.
2. **다중비교.** 검정 15~21개를 동시에 보므로 단독 |t|>2 는 그중 1개가 우연히 나온다.
   **Bonferroni 임계 |t|>2.8** 을 `score` 가 자동 표시한다.
3. **두 지평 부호 일치**를 같이 본다(D105 — 클래스 평균이 지평에 따라 뒤집힌 전례).
4. **레짐 라벨.** 이 창은 −27% 폭락이었다. 폭락장의 IC 는 평시로 일반화되지 않는다.

## 첫 관측 (2026-07-31 · 런 15개 · 판정 가능 7칸)

### 🚨 그리고 이 표가 만들어지는 동안 **작은 표본이 한 번 더 거짓말했다**
`mention_z` 는 처음 **n=7** 로 들어왔을 때 **IC −0.029 · 필요n 44(~2개월)** 였고, 그 자리에서
*"가장 빨리 답이 나오는 새 축"* 이라고 읽혔다. `inflection.db` 를 최신까지 다시 빌드해
**n=14** 가 되자 **IC −0.006 · 필요n 757(~3년)** 으로 **신호가 증발했다.**
⇒ **필요n 자체가 작은 n 에서는 못 믿는 추정치다.** 이 열은 "언제쯤 갈릴지"의 **눈대중**이지
약속이 아니다. **n<10 인 칸의 필요n 을 인용하지 마라.**

⚠ **아무것도 확정되지 않았다** — `vol_surge` 조차 Bonferroni 미달이다.
★ 그러나 **`vol_surge` 는 두 지평(h=1 −2.08 · h=5 −1.91)에서 부호가 같고**, 이는
**M224**(스윕 4축 ρ −0.21~+0.19, n=22)와 **독립적으로 같은 방향**이다 — 두 번째 측정이 첫 번째와 일치.
🚨 **그런데 `sector_flow` 의 🟢 판정은 `vol_surge` 를 양의 가중으로 쓴다.** 부호가 확정되면
게이트를 뒤집거나 빼야 한다. **확정 전에는 바꾸지 않는다**(P4).

## 축을 추가하는 법 — 이 유닛을 고치지 않는다

생산자가 `out/ic/axes/{market}_{run}.json` 에 `{"축이름": {"티커": 점수}}` 를 쓰면 끝이다.
`log` 가 자동으로 잡는다. **패턴 발견기가 늘어나도 이 원장은 그대로다** — 원장이 모든 생산자를
아는 신이 되면 안 된다. 첫 외부 생산자가 [axis_inflection](axis_inflection.md).

⚠ **순서가 중요하다: 눈금자 먼저, 발견기 나중.** 발견기는 거짓 패턴을 대량 생산한다
(828종목 × 지표 × 지평이면 |t|>2 가 우연히 수십 개). 눈금자 없이 발견기를 붙이면
이 리포가 2026-07-31에 두 번 겪은 일(D105·D106)을 규모만 키워 반복한다.
