# L1 · PROBE — 돌린다, 반쯤 실패한다, 변형해서 다시 돌린다 (stage)

> Phase 2. 가설을 **실제 모듈 호출**로 바꾼다. 이 스테이지의 전제는 *첫 호출은 대개 절반만
> 성공한다* 이고, 따라서 산출 단위는 「결과」가 아니라 **「v번호가 붙은 시도의 사슬」**이다.
> 실패한 v 도 지운다 — 왜 실패했는지가 다음 런의 자산이다.

## Why this exists
2026-08-09 실측, 한 가설에서 연속 3회:
- **v1** `module_disclosure_us MU` — 성공했지만 **인덱스만**(8-K 본문만 받아오고 10-K/10-Q 는 링크).
- **v2** `WebFetch` 로 10-Q 직접 — **HTTP 403**(SEC 가 일반 fetcher 를 막는다).
- **v3** *그 모듈이 방금 200 을 받아냈다* 는 사실에서 출발 → `module_disclosure_us._edgar_api._HEADERS_WEB`
  를 **import** → **200, 1.5MB, 23만 자**. 그 안에 3주 묵은 열린 모순의 답이 있었다.

⇒ **외부 호스트가 막으면, 그 호스트와 이미 말하는 모듈이 자격증명을 소유한다. 새 세션·UA 를 짜지 말고
import 해라(P1).** 재구현했으면 403 에서 멈췄을 것이다.

그리고 별개로: **`--help` 가 죽는 도구를 만나면 그게 그 도구의 호출 0 을 설명할 수 있다.**
실측 — `scripts/risk_units.py` 는 `help=` 문자열의 맨 `%` 때문에 argparse 가 `TypeError` 로 죽었다.
모르는 스크립트에 사람이 제일 먼저 치는 게 `--help` 다. 한 글자 오타가 **R10 을 죽인 도구**를 3주간
접근 불가로 만들었다.

## What this stage does
- 가설마다 호출을 **v1, v2, … 로 번호를 붙여** 실행하고, 각 v 에 대해 *얻은 것 / 못 얻은 것 / 그래서 다음 v* 를 적는다.
- 도구가 죽으면 **먼저 그 죽음을 고친다**(사소한 결함이면 고치고 기록, 거동 변경이면 사람 승인 항목으로 등록).
- 외부 접근이 막히면 **재구현 대신 소유 모듈 import**. 이 스테이지에서 새로 짠 HTTP 세션·인증 헤더는 EXIT 실패다.
- 얻은 숫자마다 **등급을 붙인다**: `[1차]` 내가 원문에서 직접 읽음 · `[2차]` 보도·요약 · `[추론]`.
  1차와 2차를 같은 문장에 섞지 않는다 — 2차는 **다음 런이 검증할 몫**으로 링크와 함께 남긴다.

## ✅ EXIT CHECK
- [ ] 모든 프로브가 v번호 사슬로 적혔고, 실패한 v 의 사유가 남았다(성공만 적으면 EXIT 실패).
- [ ] 외부 호출 재구현 0건. 막힌 호스트는 소유 모듈의 프리미티브를 import 해 통과했다.
- [ ] 실행 중 발견된 도구 결함이 「고침 / 사람 승인 대기」로 분류돼 기록됐다.
- [ ] 모든 인용 숫자에 `[1차]`/`[2차]`/`[추론]` 등급이 붙었다. 2차는 1차 링크가 함께 남았다.
