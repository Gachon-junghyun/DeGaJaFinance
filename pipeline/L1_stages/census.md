# L1 · CENSUS — 놀고 있는 능력의 인구조사 (stage)

> Phase 0. **가설을 세우기 전에 실험장을 잰다.** 이 리포가 소유한 실행표면 중 데스크가 한 번도
> 부르지 않은 것을 이름으로 뽑는다. 산출은 「유휴 집합」이고, 그게 다음 스테이지의 가설 재료다.
> 판단 없음(P4) — 세기만 한다.

## Why this exists
`handoff/README.md` 가 자기 도구표 서문에 이렇게 적어놨다: *"아무도 안 부르는 능력은 존재하지
않는 능력이다 — 이 폴더 전체가 그 실패 때문에 만들어졌다."* 그리고 **그 표 안에 아무도 안 부른
명령이 들어 있었다**(`scripts/measure_ic.py`, 등록 3주 뒤 호출 0). 자기 지침을 자기가 어긴 것을
아무도 못 본 이유는 단순하다 — **셀 줄이 없었다.**

## What this stage does
- `module_*` 디렉토리와 `scripts/*.py` 를 열거해 실행표면 전체를 만든다(MODULE_MAP 이 아니라 **파일
  시스템**에서 — 지도에 없는 것도 잡아야 한다).
- 각각에 대해 `pipeline/` · `llm_outputs/` · `REPORT/` 에서 **실제 CLI 호출문**을 센다:
  `python … -m module_X` · `scripts/X.py`. **파일 언급 수로 세지 마라** — 실측 3~15배 부풀려진다
  (`module_flow` 언급 172건 vs 호출 11건 · `module_inflection` 언급 5건 vs 호출 0건).
- 세 갈래로 분류한다:
  **(a) 완전 유휴** = 세 곳 모두 0 → 최우선 가설 재료.
  **(b) 배선 안 됨** = `pipeline/` 0 인데 `llm_outputs/` > 0 → 사람이 임시로만 썼고 프로토콜이 안 부른다.
  **(c) shim·부트스트랩** = `flow_read` · `_repo_path` 처럼 호출 0 이 정상인 것 → 유휴 아님, 제외 사유를 적는다.
- 유휴 항목마다 MODULE_MAP 의 **「소유」 열**을 옆에 적는다. *무엇을* 안 쓰고 있는지가 가설의 크기다.

## ✅ EXIT CHECK
- [ ] 실행표면을 파일시스템에서 열거했다(지도 신뢰 금지). 모듈 수·스크립트 수가 적혔다.
- [ ] 호출 수는 **CLI 호출문 기준**이다. 언급 기준 수치를 함께 적어 배율을 드러냈다.
- [ ] (a)/(b)/(c) 세 갈래로 분류됐고, (c) 는 제외 사유가 한 줄씩 붙었다.
- [ ] 유휴 항목마다 그것이 소유한 기능이 적혔다 — 이름만 나열한 목록은 EXIT 실패.
